Architecture du code

Chaque script d'expérimentation délègue l'inférence GPU au moteur central via sys.argv + import main.

⚙️
run_eval_osm_gpu.py

Moteur d'inférence GPU

Charge le modèle, applique l'adaptateur LoRA, boucle d'évaluation avec checkpoints atomiques et reprise automatique.

🧠
strategies_osm.py

Stratégies CoT / ToT / GoT

Implémentation des trois stratégies. Accès au KG OSM via Nominatim avec cache local de 1107 entrées.

🔧
finetune_gptoss.py

Fine-tuning LoRA

Fine-tuning avec SFTTrainer (TRL). Construit les prompts instruction-following, attache les adaptateurs LoRA r=8.

📊
analyze_96_experiments.py

Analyse & Visualisation

Charge les 15 checkpoints, calcule métriques globales et par prédicat, génère matrices de confusion et graphiques PNG.

🧪
exp1…exp6_*.py

Scripts d'expérimentation

Définissent la configuration (adaptateur, budget tokens), vérifient les checkpoints existants, appellent le moteur central.

💾
results/ + osm_cache.json

Sorties

Cache OSM, checkpoints JSON par stratégie avec reprise, PNG des matrices de confusion et graphique comparatif.

strategies_osm.py

Stratégies de raisonnement

Chaque stratégie enrichit le prompt avec les preuves OSM avant d'appeler le LLM. La différence est dans la structure et le nombre d'appels.

CoT · Chain-of-Thought

Raisonnement en chaîne

Construit un unique prompt enrichi avec toutes les preuves OSM (coordonnées, bounding box, hiérarchie administrative) et demande au modèle de raisonner étape par étape avant de donner un prédicat DE-9IM.

1 appel LLM / exemple
ToT · Tree-of-Thought

Raisonnement arborescent

Génère plusieurs hypothèses de prédicats (branches), évalue chacune avec un prompt distinct, puis sélectionne la meilleure via vote ou score de confiance.

N appels LLM / exemple
GoT · Graph-of-Thought

Raisonnement en graphe

Décompose en étapes interdépendantes : extraction des preuves → analyse géométrique → comparaison → conclusion. Chaque nœud est une génération LLM distincte avec contexte accumulé.

K appels LLM / nœud
GeographicKnowledgeGraph · strategies_osm.py

Classe centrale d'accès au KG OSM. get_neighborhood_details(place) interroge Nominatim et retourne coordonnées, type de lieu, bounding box et hiérarchie administrative. Résultats mis en cache dans results/osm_cache.json (1 107 entrées) pour éviter les requêtes réseau répétées.

run_eval_osm_gpu.py

Fonctions du moteur

Logique interne du moteur d'inférence central : patches, checkpoints, boucle d'évaluation.

Patches de compatibilité appliqués au démarrage

_TorchvisionStubFinder

torchvision cassé sur ce serveur (_cast_Long manquant). MetaPathFinder qui intercepte tous les imports torchvision.* et retourne des stubs vides avec InterpolationMode correct.

torch.accelerator

Attribut manquant dans PyTorch < 2.4. Polyfill ajouté avant tout import de transformers pour éviter AttributeError au chargement.

nn.Module.set_submodule

Méthode absente avant PyTorch 2.5. Polyfill implémentant la traversée récursive du graphe de sous-modules.

supports_quant_method

Bug transformers ≥5.9 : crash si quantization_config=None. Méthode remplacée par une version qui retourne False sur entrée nulle.

_save_json_atomic(path, data)
Sauvegarde via fichier temporaire + os.replace atomique. Garantit que le checkpoint JSON est toujours valide, même si le processus est interrompu en cours d'écriture.
_load_checkpoint(ckpt_path)
Charge le checkpoint existant (indices déjà traités + résultats). Retourne un dict vide si absent ou corrompu. Permet la reprise automatique sans retraiter les exemples déjà évalués.
evaluate_strategy(strategy, df, output_dir, model_tag)
Boucle d'évaluation principale. Pour chaque exemple non traité : appelle la stratégie → prédit un prédicat → compare à la vérité terrain → sauvegarde le checkpoint. Précision affichée en temps réel dans la barre tqdm.
gpu_inference_fn(prompt)
Inférence GPU locale. Tokenise avec troncature à max_position_embeddings − max_new_tokens. Génère via model.generate() (température 0.1). Logue la latence du premier appel (~5s sur A100).
_local_hf_hub_download(repo_id, filename)
Patch PEFT pour chemins locaux. Intercepte les appels HuggingFace Hub quand repo_id est un chemin absolu. Cherche dans le dossier et son parent, avec fallback .bin → .safetensors.

Conclusions

Observations clés

🏆

GoT + KG Ollama domine

Le modèle base sans fine-tuning avec GoT enrichi par KG OSM atteint 74.0% — meilleure performance toutes configurations confondues.

⚠️

Fine-tuning non suffisant seul

Les modèles fine-tunés ne surpassent pas systématiquement le base. Le fine-tuning améliore GoT (61.5%) mais dégrade CoT (53.1% vs 57.3%).

📈

GoT > CoT > ToT

GoT bénéficie le plus du KG OSM. ToT est systématiquement la stratégie la moins performante sur ce type de tâche de classification topologique.

🗺️

within et disjoint : faciles

Le modèle base atteint 100% sur within en CoT. crosses et overlaps restent les prédicats les plus difficiles à prédire.
