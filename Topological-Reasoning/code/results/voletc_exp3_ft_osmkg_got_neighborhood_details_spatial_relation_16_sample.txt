This repo contains a minimal demo of spatial reasoning using OpenStreetMap (OSM) data. The system uses the OSM2Vec embeddings to quickly retrieve relevant entities and then applies a set of spatial predicates to determine the spatial relationship.

## Spatial Predicates

| Predicate | Description |
|-----------|-------------|
| contains | A fully contains B |
| within | A is fully within B |
| touches | A and B share a boundary edge but no interior points |
| crosses | A geometrically crosses B |
| disjoint | A and B share no points |
| overlaps | A and B partially share area |
| equals | A and B are spatially equal (identical geometry) |

## Demo Example

**Question**: Does the city of San Francisco spatially equal the San Francisco County boundaries?

**Answer**: YES

### Reasoning Steps

1. **Entity Retrieval**: Used OSM2Vec to fetch spatial data for "San Francisco" and "San Francisco County".
2. **Spatial Validation**: Queried the spatial engine to check equality.
3. **Result**: The spatial engine returned `true` for equality.

## How It Works

- **Entity Matching**: OSM2Vec embeddings provide rapid semantic entity resolution.
- **Spatial Engine**: Uses JTS (Java Topology Suite) via PyGEOS to perform spatial predicates.
- **Geometric Equality**: Directly uses the `equals` predicate to verify exact spatial match.

# OSM GeoSpatial Disambiguation

This repo contains the code for the OSM GeoSpatial Disambiguation challenge.

## Problem Statement

Given two geographic entity names, A and B, determine the spatial relationship between them using the [DE-9IM](https://en.wikipedia.org/wiki/DE-9IM) model.

Possible relationships:
- **contains**: A fully contains B.
- **within**: A is fully within B.
- **touches**: A and B share a boundary point but their interiors do not intersect.
- **crosses**: A and B intersect but neither contains the other.
- **disjoint**: A and B share no points.
- **overlaps**: A and B partially share an area but neither contains the other.
- **equals**: A and B are spatially identical.

### Rules
1. **Entity Validation**: Use the OSM GeoSpatial API to fetch entity data. If the entity is not found or the name is ambiguous, treat it as invalid.
2. **Spatial Disjoint**: Entities are guaranteed to be spatially disjoint.
3. **Geometric Reasoning**: Use pure spatial geometry to reason the relationship.

### Examples

| Entity A | Entity B | Spatial Relationship |
|---------|---------|------------------------|
| Sahara Desert | Sahara Desert | equals |
| City of New York | State of New York | within |
| Trans-Alaska Pipeline | State of Alaska | crosses |
| State of Alaska | Contiguous United States | disjoint |
